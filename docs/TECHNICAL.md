# 기술 설명

## 디스크

- MODE2/2352 원시 이미지, 트랙 1개, ISO9660. 파일을 같은 크기로 제자리 교체하고 바뀐 섹터의 EDC/ECC(Mode 2 Form 1)를 다시 계산합니다(`tools/cdecc.py`, 원본 섹터로 검증, numpy 일괄 처리판 포함).
- 바뀌는 파일: `SLPM_621.27`(실행파일), `PSXDATA/GAME/FONT.PRT`(폰트 텍스처), `PSXDATA/MOVIES/*.PSS`(동영상 6편).

## 게임 텍스트

- 일본어 텍스트는 모두 실행파일 안의 **u16 글리프 번호 문자열**입니다. 코드 `0x80+n` = 글리프 n, `0x20` 공백, `;`(0x3B)·`/`(0x2F)는 버튼 아이콘 제어, `0` 종결.
- 문자열 풀: 파일 오프셋 `0xCE650–0xD0080`(216개) + `0x1331C0–0x1331F8`(예/아니오 등 7개). 총 223개.
- 화면 배치 레코드(12바이트: 문자열 포인터 u32, x i16, y i16, 정렬·크기 4바이트)가 문자열을 가리킵니다. 빌드는 풀을 번역문으로 다시 채우고(같은 문장은 공유) 레코드 포인터를 새 위치로 고칩니다.
- 실행파일에 남아 있는 영어 문자열(`Press START…` 등)은 일본판에서 쓰이지 않아 건드리지 않았습니다.
- `0xCFF70` 의 "□ボタンで再試行" 은 원본에서도 테이블 밖 글리프(430번)를 쓰는 문자열로, 쓰이지 않는 것으로 보입니다(번역은 해 둠).

## 글꼴

- `FONT.PRT` 는 텍스처 뱅크입니다: 헤더 0x20(`01 02 03 04`, `0x10000000`, 팔레트 수, 텍스처 수) → 팔레트(256색 RGBA, 알파 0x80=불투명, CSM1 스위즐) → 텍스처마다 16바이트 헤더(log2 폭, log2 높이, psm(하위 바이트, 상위 바이트=밉맵 수), 바이트 크기, 팔레트 번호) + 픽셀. 24비트 텍스처는 32비트 단위로 저장됩니다(`tools/tex.py`).
- 일본어 글꼴은 6번째 텍스처(512×512 8bpp, 파일 끝, 아래→위 저장)이고, 게임에 실제로 쓰인 430자만 들어 있습니다.
- 글리프 레코드: 실행파일 `0xD8CD0` 부터 430개 × 48바이트 = `[x0, y0, 0, 1, x1, y1, 0, 1]`(쿼드 크기) + `[u0, v0, u1, v1]`(UV, v = 1 − 행/512). **쿼드가 UV 앞**에 옵니다.
- 한글화: 번역에 쓰인 기호(숫자, ○×□△, L1/L2/R1/R2, 영문자, 「」 등 45자)는 원본 글리프를 그대로 옮기고, 나머지 칸에 한글 344자와 `.` `,` 를 새로 그려 아틀라스를 다시 배치했습니다(385/512 행 사용). 한글 칸은 20×23 텍셀, 쿼드 (−10, 22)–(10, −1).

## 이미지

텍스처 1,890장을 모두 풀어 확인했습니다. 일본어가 그려진 이미지는 폰트 텍스처뿐이고, 메뉴 문구도 모두 폰트 텍스트입니다.

## 동영상

- `PSXDATA/MOVIES/*.PSS`: MPEG-2 프로그램 스트림. 영상 E0(640×368, 30fps, 불규칙 GOP·열린 GOP), 음성 BD(`SShd` type 1 = 16비트 PCM, 48kHz 스테레오, 0x200 인터리브).
- 음성 추출(`tools/movie/pssaudio.py`) → faster-whisper large-v3 받아쓰기(VAD 사용/미사용 두 벌 대조) → 번역 `translation/movie/*.tsv`.
- 자막 합성 후 고정 양자화 14벌을 원본과 같은 자리의 I 프레임(닫힌 GOP)으로 인코딩 → GOP 마다 원본 영상 패킷 일정(최대 4프레임 지연)에 맞는 벌을 골라 이어 붙임(`gopsplice.py`) → 원본 PSS 틀(팩·음성 패킷 위치)에 영상만 채움(`psmux.py`). 음성 바이트와 파일 크기는 원본과 같습니다.
